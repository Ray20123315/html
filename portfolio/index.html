Build principles

做出來，
再把它
做對。

01

先讓系統可運作

從最小可用版本開始，把資料流、狀態與失敗模式跑通，再做外觀與擴充。

02

把風險寫成邊界

更新、完整性、回復、權限、外部 API 與平台限制，都應該能被清楚看到，而不是藏在 UI 後面。

03

跨領域不是亂做

AI、Web、Windows 與 Minecraft 看起來很遠，但核心其實都是 state、data、interface 與可靠性。

04

讓作品自己說話

Repository、Release、文件與可執行成果比抽象形容更有說服力；這個網站只是把入口整理得更清楚。
