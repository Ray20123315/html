OBSERVE FIRST

先量對，再談「最佳化」。

beta.29 把 Windows 真正的 Commit 壓力、Process Commit、Page File、Headroom 與趨勢放在一起。1 ms 是資料取樣要求，不等於 UI 每毫秒重畫。

01

Process Commit Charge

使用 Windows PrivateUsage，而不是把 Working Set 或 .NET PrivateMemory 當成 Commit。

02

Commit Δ + Leak trend

看近期增長量與多次樣本的持續成長，降低單次尖峰誤報。

03

Commit Headroom + ETA

回答「離 system commit limit 還有多遠」，並用近期趨勢估算 ETA。

04

Page File Health

用白話顯示 Windows 是否自動管理 Page File，以及 Commit Limit 是否有足夠餘裕。

05

Adaptive Refresh

Telemetry 與 UI refresh 分離；視窗、前景與遊戲狀態決定合理畫面更新頻率。

06

Emergency Rescue

壓力真的高時才顯示救援面板，先看大用量 App、正常關閉、再考慮工作管理員。

INCIDENT & RELIABILITY

當機之後，先還原時間線。

Previous Crash Analyzer 把上一輪 heartbeat、persistent Flight Recorder 與 Windows Event Log 串在一起。Event 41 / 6008 只表示異常關機序列，不單獨宣稱是電源、RAM 或某個程式造成。

  • Resource Exhaustion Event 2004：低虛擬記憶體／Commit 壓力證據
  • BugCheck / WHEA：分開標示，不跟記憶體壓力混成同一原因
  • Incident-only Support Bundle：只匯出事故附近的小時間窗
  • Reliability History：把近期相關事件整理成可讀列表

REVERSIBLE RULES

Game Memory Reserve V2：不是鎖 RAM。

只有你建立 Per-App Rule 並打開總開關後，符合「背景時間 + Commit 門檻」的普通 App 才可能暫時降低 Windows Process Memory Priority。遊戲、前景、反作弊、語音、輸入與核心程序保持原設定。

DEFAULT總開關預設關閉

第一次啟動不會自行修改任何程序 Memory Priority。

PROTECT硬保護清單

Foreground / Game Profile / anti-cheat / voice / input / Windows core 都不降。

RESTORE條件消失就還原

變成前景、規則停用、程式不再符合或 App 結束時，要求回復原 Memory Priority。

UPDATE / OEM

更新能驗證；OEM 控制不越界。

Update Center 直接讀 GitHub Releases 的 prerelease、Release Notes、asset 大小與 SHA-256 digest。設定支援 Backup / Rollback；還原前會再建立 safety backup。

MSI OEM Control Center

讀 BIOS 廠牌／機型並安全偵測 MSI Center；需要風扇、功耗、效能情境時開啟 MSI 官方程式。沒有公開安全介面時，不直接寫 EC / MSR / 私有 register。

INSTALLER V2

「安裝」是真的 install / repair / uninstall。

Windows CI 每次都在隔離目錄執行完整週期：安裝後核對 payload SHA-256、repair 後再次核對、最後 uninstall 並確認目錄沒有殘留。正式安裝同時建立 Start Menu 與 Installed Apps 資訊。

SAFETY BOUNDARIES

把「不做什麼」也寫清楚。

01

不亂殺程式

Emergency Rescue 先建議正常關閉；系統與受保護程序不自動終止。

02

不把 Event 41 當根因

異常關機事件只當時間線證據，根因需要更多事件與趨勢佐證。

03

不直接寫未公開 MSI EC

OEM 硬體控制交由 MSI Center，避免跨機型 EC 風險。

04

不假裝有可信簽章

beta.29 目前沒有正式 Code Signing PFX，因此 Release 是 unsigned；不宣稱能繞過 SmartScreen / Smart App Control。

Memory Manager

先看懂，再決定要不要動。

beta.29 已在 GitHub Actions 的 Windows runner 通過 app self-test、Memory Priority round-trip、設定 rollback、Installer V2 與 SHA-256 manifest 驗證。實體 MSI 機器仍需要最後的視覺、MSI Center 與 SmartScreen 驗收。
